# Рекомендація для команди (Task D)

Синтез Task A (`docs/tool-matrix.md`), Task B (`docs/comparison.md`) та
Task C (`docs/agents-md-notes.md`).

Контекст команди, під який дається рекомендація: розробка в JetBrains IDEA,
TypeScript/Node, робота з клієнтським кодом під NDA, є CI на GitHub Actions.

## Рекомендований основний (primary) інструмент

**GitHub Copilot (Agent mode, плагін для JetBrains IDEA)**

Чому: на реальному прогоні тікета BUG-101 (Task B) він закрив задачу
**з одного промпту за ~4 хв** — без уточнень, з правильною причиною бага
(а не симптомом), із трьома регресійними тестами та чистим `typecheck`.
Критично, що він сам обрав послідовність «спершу падаючий тест — потім фікс»,
тобто довів наявність бага, а не вгадав фікс. За матрицею (Task A) він дає
найдешевший передбачуваний вхід для команди ($10/міс Pro, $19/user Business)
і при цьому закриває головну для нас вимогу приватності: на Business/Enterprise
код не використовується для навчання за замовчуванням, є content exclusion та
audit log. Підтвердження на запуск кожної термінальної команди, яке в матриці
виглядало мінусом, на практиці виявилось прийнятною ціною за контроль —
на задачі такого розміру воно не сповільнило роботу.

## Рекомендований додатковий (secondary) інструмент

**Claude Code (CLI)** — для сценаріїв: масові/довгі рефактори через кілька
файлів, автоматизація в CI (headless `claude -p`), робота з репо без
відкритої IDE, генерація рутинних змін за тікетом (патерн Task E).

Чому: це єдиний з трьох інструментів із повноцінним headless-режимом, тож
лише він придатний для кроків у CI-пайплайні. Його автономний цикл
read→edit→bash→test без нагляду виграє саме там, де Copilot змушує
підтверджувати кожну команду, — на довгих ланцюжках із десятків кроків.
Для NDA-проєктів його можна пустити через Amazon Bedrock / Vertex, і тоді
код не проходить через інфраструктуру Anthropic взагалі.

**JetBrains AI Assistant + Junie** свідомо лишаємо поза стеком за замовчуванням:
його головна перевага — локальний PSI-індекс для «знайди всі usages / перейменуй
символ» — у JetBrains IDEA вже доступна штатними засобами IDE без AI. Платити
другу підписку ($10–30/міс на людину) за перекриваний функціонал недоцільно;
має сенс повернутись до нього лише якщо знадобляться локальні моделі
(Ollama/LM Studio) для коду, який взагалі не може виходити в мережу.

## Ключові компроміси (trade-offs)

- **Ціна vs автономність.** Copilot Pro $10/міс проти Claude Max $100–200/міс.
  Дорожчий інструмент купує не якість фікса (на BUG-101 різниці в результаті
  не було б — задача тривіальна), а можливість не сидіти над агентом і
  headless-режим. Для щоденних дрібних правок це переплата; для нічних
  рефакторів у CI — єдиний варіант.
- **Якість індексації vs приватність.** Хмарний семантичний індекс Copilot
  добре шукає по великому репо, але вимагає завантаження коду; локальні
  моделі JetBrains не покидають машину, але помітно слабші. Компроміс
  вирішується не інструментом, а тарифом: Business-tier + content exclusion
  або Bedrock/Vertex.
- **Крос-tool портативність (AGENTS.md) vs глибина tool-specific фіч.**
  Task C показав, що спільний `AGENTS.md` покриває ~90% потреби (стек,
  команди, guardrails, DoD) і читається всіма інструментами. Але Skills,
  subagents і hooks Claude Code в нього не переносяться — це плата за
  портативність.
- **Підтвердження команд vs швидкість.** Пер-command approval Copilot ловить
  небезпечні дії, але на 30-кроковому завданні перетворюється на клікання.
  Практичне рішення — тримати обидва інструменти й обирати за довжиною
  ланцюжка, а не «один назавжди».
- **Автономність vs розростання скоупу.** На Task B Copilot додав guard на
  відʼємний `maxLength`, якого тікет не вимагав. На дрібній задачі це плюс;
  чим автономніший інструмент і більший тікет — тим дорожче обходиться
  незамовлене в code review.

## Ризик/застереження, за яким варто стежити

**Непередбачуваність лімітів і тарифів, а не vendor lock-in.** Технічний
lock-in тут низький — `AGENTS.md` портативний (доведено в Task C), а код
залишається звичайним TS. Реальний ризик — економічний: у Copilot
преміум-запити тарифікуються множниками моделі, у Claude — 5-годинними
rolling-вікнами плюс тижневим лімітом. Обидві схеми означають, що вартість і
навіть **сама доступність** інструменту залежать від політики вендора, яку
переглядали вже кілька разів за останній рік. Практичний захист: (1) не
вбудовувати жодного інструменту в CI як блокуючий крок, поки немає фолбеку;
(2) раз на квартал перезвіряти рядки «Ціна та ліміти» в `docs/tool-matrix.md`;
(3) тримати `AGENTS.md` актуальним — це страховка, яка дозволяє перемкнути
команду на інший інструмент за день, а не за спринт.
