## Що саме змінилось у коді (фінальний фікс)

`app/src/text-utils.ts` — публічна сигнатура не змінена:

```ts
const limit = Math.max(0, maxLength);

// The suffix counts against maxLength, so the result never exceeds the limit.
if (suffix.length >= limit) {
  return suffix.slice(0, limit);
}

return input.slice(0, limit - suffix.length) + suffix;
```

`app/src/text-utils.test.ts` — додано 3 тести:

1. `counts the suffix against maxLength (BUG-101)` — точний сценарій з тікета:
   `truncate("a long sentence here", 10, "...")` → `"a long ..."`, довжина `10`.
2. `never returns a string longer than maxLength` — табличний тест на 4 входах,
   інваріант `result.length <= maxLength`.
3. `returns the suffix clipped to maxLength ...` — edge case
   `suffix.length >= maxLength` (`maxLength` = 3, 2, 0), не кидає виняток.

**Доказ, що тести справді ловлять баг:** на нефіксованому коді вони падали
(`Tests 3 failed | 6 passed`, `expected 'a long sen...' to be 'a long ...'`),
після фікса — `Tests 9 passed (9)`.

На цій задачі Copilot в Agent mode впорався з **першого промпту** без жодного
уточнення — тікет виявився достатньо детальним (є очікуваний вихід і edge case),
тож інструменту не довелось нічого домислювати. Найцінніше в його поведінці —
не сам фікс (він тривіальний), а порядок дій: спершу відтворити баг падаючим
тестом, потім правити. Це те, що варто окремо перевірити в решті інструментів:
чи вони теж доводять наявність бага, чи одразу переписують реалізацію «на віру».

Друга річ, на яку варто дивитись у порівнянні, — **обсяг незамовленого**:
Copilot додав guard на відʼємний `maxLength`, якого тікет не вимагав. Це
корисно, але формально виходить за рамки — інструменти з більшою автономністю
(CLI-агенти) схильні розширювати скоуп сильніше, і на великому тікеті це вже
мінус, а не плюс.
